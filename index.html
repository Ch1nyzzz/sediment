ICL 记忆的最佳形态，以及把它蒸馏进参数能拿到多少

主线：agent 部署任务流上，先确定“哪种上下文记忆真的有用”，再把这份记忆用在线蒸馏写进权重，使推理时不带任何记忆也能变强。本页汇总 2026-08-22 → 08-28 的可复算结论。

三句话结论：

  • 形态：生成前只注入 一条 已知成功、任务文本最相似的完整轨迹最好（101/512，无记忆基线 86）。把多条记忆／反思拼在一起一律更差，甚至显著差于完全不给记忆。
  • 时机：Recuris 式 call-time 拦截注入与词法 working-state 在 4B/8B 上都没有可开采增益；拦截是结构性有害的（模型把范例当“照做”而非“参考”）。
  • 内化：把这条记忆用 reverse-KL 在线蒸馏进 LoRA 后，在 9 个从未训练也从未被检索的家族上做 prompt-only 评测，450 题 80 → 90（+2.2pp，p=0.13）；训练流内 400 题 18 → 27（p=0.035）。

02结论一：哪种 ICL 记忆最好用

答案是一条，不是四条；是完整可执行的成功轨迹，不是压缩过的经验教训；筛选发生在生成之前，用的是 source 端本来就已知的成功标签。

关键不是“101 比 68 多 33 题”，而是同题 discordance：success rank1 对 top4 reflection-only 是 48/16（p=7.7e-5），对 top4 compiled 58/25（p=3.8e-4），对 top8 compiled 59/19（p=6.4e-6）。而 top4 compiled 与 top4 reflection-only 之间是 29/28（p=1.0）——抽取式压缩器没有净修复任何东西；top4 与 top8 之间 30/23（p=0.41）——更深的 source 覆盖也没有收益。多条记忆的失败不是“太长被截断”（512/512 都完整注入且远低于 32k），是注意力稀释与跨环境规则冲突。

两个副产品结论

  • top-n 里确实有被浪费的信息，但目前取不出来。rank1–4 各自单独注入是 88/84/85/92，四个 rank 的 oracle 并集是 137/512，远高于最佳单 rank。只用 source bank 训练的 reward-blind verifier 从 5 个候选里选一条能到 105/512（vs frozen 33/14，p=0.008），计算曲线 86/99/103/105/105 —— 但它每题要 5 次 actor rollout，不满足部署约束，只作为“rank 之间存在互补性”的诊断上界。
  • 历史“k=4 检索”其实一直是 top-1。experience.py 的预算逻辑无条件放入第一条 peer，而单条 peer 渲染后中位 5,953 字符已超过 4,000 的块上限，第二条永远进不来：实测全流每题实际 peer 数为 {0: 16 题, 1: 784 题}，同族占 84.6%。也就是说旧的“最强朴素基线”是一个强同族 top-1，这与新实验的结论方向一致。matched legacy 96 vs matched frozen 81（41/26，p=0.086）。

03结论二：注入“时机”这条轴没有增益

结论一说的是注入什么。Recuris（arXiv 2608.24876）主张经验记忆是 invocation-conditional 的——价值取决于什么时候注入。我们把它的两个机制原样移植：① call-time 单条注入（模型起草修改类工具调用时拦截不执行，回灌一条最相似的 donor 步骤让它重起草；报错时在观测末尾追加恢复步）；② 词法 working-state（目标账本，只有成功的写调用才能标记 done）。同池、同 bank、同协议。

为什么拦截会崩（取证，不是猜测）。4B 上拦截后 72% 的重起草改了动作，但改的方向是错的：跨族 donor 时它把写操作换成查询（cancel_reservation → get_hospital_by_name）并且相当一部分写操作再也没补回来——论文最在意的 omitted-write 反而被我们制造出来。把拦截语从“未执行，请对照”改成“已排队，请重发”后是 42/512，仍然显著更差，问题不在措辞。换成同族 bank 更狠（17/512）：82% 的重起草直接照抄 donor 那一步的工具，44 次连参数值一起抄。8B 上则是另一种失败——93% 的重起草原样重发同一调用，hint 被彻底无视，只剩下错误数 1526 vs 1075 的搅动。

working state 的病是 checker 不准 + 强制完成：通用词法 checker 只能把 49% 的目标标成 done，footer 又要求“每条目标都要有成功写回执才能结束”，于是模型对已完成但仍标 pending 的目标重复写，重复写 403 vs 47、撞 30 步 80 vs 7。Recuris 的 working-state 增益（+23.9）靠的是演化出来的领域特定 checker，那是我们无法免费获得的一层。

模型越强，越靠“同族的具体经验”。8B 上跨族块的增益消失（+5，p=0.62）而同族块成为唯一显著正向（+24，p=0.006，增益分散在 env_179/183/185/189/191，不是单族驱动）。这直接回答了此前悬而未决的 E-cross 问题：8B 的可用 ICL 教师信号来自 within-family 记忆，跨族 bank 在 8B 上没有教师优势。评测流因此必须按家族交错排，否则 within-family 适应也能撑出曲线增益，得到“正结果 + 错误归因”。

04结论三：把这条记忆蒸馏进参数，能拿到多少

如果记忆的价值只能靠推理时塞进上下文兑现，那它每题都要付 6k 字符的成本，而且换个家族就失效。真正要证的是：能不能把它写进权重，使推理时不带记忆也变强，并迁移到没训练过的家族。

方法：mean16 reverse-KL 自蒸馏（无 compiler、无额外模型）

环节设置为什么是这个
学生裸 rollout：prompt-only，不给任何记忆它同时是在线成绩与on-policy 状态分布——流曲线本身就是内化度量，不需要另设评测
教师同一份权重，读 prompt + 1 条 success-first rank1 完整轨迹，在学生自己的轨迹上打分自蒸馏，目标永不陈旧；不需要第二次 actor rollout
目标reverse KL(student ‖ teacher)，top-k=20部署时模型跑的是 prompt-only，期望必须在学生分布下取。教师采样轨迹上的 forward KL 实测只有 0.008 nats——在教师自己的状态上，它说的话学生本来就会说
credit 范围每个 action token 都是 KL 位置（weight_mode=sft），不是只有过门的 ~20 个 tool-call 内部 token门控臂留下 4000 个无约束位置，每次合并烧掉 0.3 nats 的抗重复先验——这是此前所有崩溃的共同点
防遗忘anchor_kl_coef=0.5 把未教位置锚回 base；grounded_weight=0.2 抑制可从上下文抄的参数值侵蚀正是骑在“可复制参数值”这个通道上

frozen 内化后（不带记忆）

量级怎么读。ICL 把记忆放在上下文里、每题付 6.2k 字符，在 512 池上拿到 +15（+2.9pp）。蒸馏之后推理端零额外 context，在 450 题未见家族上拿到 +10（+2.2pp）。两者任务池不同、不能直接相除，但量级是同一档：上下文里的增益有相当一部分确实被写进了权重，并且跨家族迁移了。这是本项目第一次拿到“内化 + 迁移”同时成立的证据。

05为什么目标函数长这样：五个被证伪的设计

上面那套目标函数不是选出来的，是被五次失败逼出来的。每一条都有独立取证。

① δ 门在训模型做它已经会的事

同一批 314 个过门 token 上两个目标各算一次：CE 均值 0.365 nats vs KL 均值 3.538 nats。那条贴着 frozen 的平线不是“学坏了”，是梯度≈0，根本没学。KL 约 10× 信号 —— 目标函数从 CE 换成 full/reverse-KL 的直接依据。

② 无门控累积必崩，先涨后崩

160 题流上 ng 臂前 5 窗 12 vs 8 领先，w4 毒合并后探针 0.75 → 0.17，w5–6 的 32 题全部撞满 30 步、reward 0（“循环查询永不结算”）。此前 48 题冒烟的 W-AUC 0.700 是崩溃前的截断。

③ 毒源是观测通道，不是失败轨迹

两次独立毒合并、从同一父版本训三个变体各测 12 探针：obs-only 0.167/0.167、act-only 0.667/0.583、both 0.250/0.083（父 0.417）。观测 CE 把病人档案、log_id 这类实例数据背进了权重，且策略与世界模型共用同一个 4B LM 时会泄漏进策略。→ train_channels=act。

④ 剂量与证据脱钩 / 负信用落在框架 token

加权平均损失让证据质量只有 0.6–1.7 单位的样本驱动满剂量更新（act-only loss 四步从 4 掉到 0.001）→ 加 w_norm_floor。负信用一旦落到 <tool_call>／JSON 键上，模型会退化成只叙述不调用工具→ 语义掩码：框架 token 任何符号都不给信用。

⑤ meta 参数 compiler 的预注册试点未通过

“把一个 16 条记忆窗口学成低维 LoRA 更新”的 family-held-out 试点：三条中心判据全部失败，且部署门拒绝了全部 24 个测试预测（write_rate=0，系数恒为 0，合成 adapter 与参考张量逐位相等）。因此观察到的 stable/shuffled 正增益不可能来自任何学到的更新，它测的是同一份参数两次评测之间的重放噪声。结论：安全 no-op 行为按设计工作，但该学习器没有提取到有用的记忆依赖更新——路线已回滚，不做放大。

⑥ lesson compiler 路线已弃

“memory → RULE/AVOID/TEMPLATE lesson → 教师 → KL”这条线不再是主线：learned hint 只是“更好的教师构造”，与既有工作同轴竞争；且抽取式 compiler 在 512 池上被实测证明没有净修复（top4 compiled 68 vs top4 原文 69，29/28，p=1.0）。当前主臂完全不用 compiler。

06现状与下一步

  • 在跑：Qwen3-8B 原生复验流水线。单个 model-native 记忆 bank（seed 0，目标 1,700 条轨迹）→ frozen 400/450 对照 → 25 窗 mean16 reverse-KL 在线训练 → held-out 450 配对。全程 enable_thinking=false，已核验 0 个 <think> 块。这条线要回答的是：4B 上的 +2.2pp 是不是小模型特有的。
  • 要补的口径：多种子 × 多流序（流式方法对任务顺序敏感，单一顺序的曲线不可信）；held-out 的 p=0.132 需要更多题量或更多盐才能收敛判定。
  • 记忆侧的下一步：8B 的结果说明教师信号在同族记忆里。若确认，评测流必须改成家族交错排，否则 within-family 适应会伪装成跨族迁移。
  • 不再做：拦截式 call-time 注入、通用词法 working-state、多条 lesson 拼接、lesson compiler、当前形态的 meta 参数 compiler。

07已知限制

  • 不是端到端共同随机数。request seed 只固定裸 prompt 的采样种子；vLLM online 模式默认不保证复现（两次 frozen 跑在固定 512 上有 26 个首响应、9 个成功、80 个 dense reward 不一致）。配对检验里仍含残余采样噪声。
  • oracle 数字不是成绩。rank1–4 并集 137/512、五候选并集 145/512 都是上界；105/512 的 verifier 需要 5× rollout，不满足“每题一次 rollout”的部署约束。
  • 发现盐 ≠ 确认盐。salt0 上的一切都是发现；只有 salt1/2 是确认，而确认集聚合尚未达到 0.05。
  • 有效样本量小于名义样本量。早期 200 题池的区分度几乎全部来自一个家族（名义 n=200，有效 n≈50）。这是后来把池扩到 512 并按家族分解报告的原因。
